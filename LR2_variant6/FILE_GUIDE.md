# Где какой файл используется

Этот файл — краткая карта проекта. Если нужно быстро объяснить структуру на защите,
ориентируйтесь по нему.

| Файл | Где используется | Что делает / что изменено |
|---|---|---|
| `Pico_SoC.v` | обе части ЛР | Главная SoC. PicoRV32 подключён к Wishbone crossbar. Добавлен третий slave `wb_ram_ip` по адресу `0x1002_0000`; `NS` изменён на 3. |
| `picorv32.v` | обе части | Готовое ядро PicoRV32. Логику процессора мы не меняем. |
| `wbxbar.v` | обе части | Wishbone crossbar. Распределяет обращения процессора между RAM, GPIO и дополнительной RAM. |
| `addrdecode.v` | обе части | Внутренняя часть `wbxbar`: декодирует адрес и выбирает slave. |
| `skidbuffer.v` | обе части | Вспомогательный модуль `wbxbar`. |
| `wb_ram.v` | обе части | **Исходная обязательная RAM**. В ней находится `firmware.mem`; этот файл не удаляется. |
| `wb_gpio.v` | обе части | GPIO slave. Через него прошивка передаёт результаты тестбенчу или светодиодам. |
| `wb_ram_ip.v` | задание 2 | Дополнительная Wishbone RAM. Именно её процессор записывает/читает для проверки СФ-блока. |
| `firmware/firmware.S` | обе части | Старт RISC-V: устанавливает stack pointer в `16368`, затем вызывает `main`. |
| `firmware/firmware.lds` | обе части | Linker script для прошивки. |
| `firmware/makehex.py` | обе части | Преобразует бинарную прошивку в текстовый `firmware.mem` для Verilog RAM. |
| `firmware/firmware_common.h` | обе части | Общие адреса GPIO/RAM и функции `read_int()` / `write_int()`. |
| `firmware/firmware_quicksort.c` | задание 1 | Quick Sort для массива из 20 `int`; выдаёт отсортированные элементы через GPIO. |
| `firmware/firmware_array_limit.c` | доп. пункт задания 1 | Тест локального массива переменного размера для поиска максимального количества элементов. |
| `firmware/firmware_wb_ram_test.c` | задание 2 | Записывает 16 слов в дополнительную RAM, читает обратно и формирует PASS/FAIL. |
| `prog_make.sh` | обе части | Компилирует выбранный C-файл RISC-V GCC и создаёт `firmware.mem`. |
| `tb_verilator.cpp` | симуляция | C++ testbench Verilator. Имеет режимы `quicksort`, `ram`, `array`. |
| `verilator_build.sh` | симуляция | Один раз собирает модель всей SoC через Verilator. |
| `run_quicksort.sh` | задание 1 | Полный автоматический запуск Quick Sort. |
| `run_wb_ram_test.sh` | задание 2 | Полный автоматический тест дополнительной RAM в Verilator. |
| `find_max_array.sh` | задание 1 | Бинарным поиском находит максимальный рабочий `ARRAY_SIZE`. |
| `de10_lite_top.v` | задание 2, ПЛИС | Обёртка для DE10-Lite: 50 МГц, KEY0 как reset, результат на LEDR. |
| `get_official_wb_ram.sh` | опционально | Скачивает оригинальный `wb_ram.v` из репозитория Alex Forencich и переименовывает модуль в `wb_ram_ip`. |
| `sim_make.sh` / `tb.v` | вспомогательно | Старый Icarus-путь из исходного проекта. Для обязательного задания 1 используйте именно Verilator. |

## Поток данных в двух строках

```text
C-программа -> RISC-V GCC -> firmware.mem -> wb_ram.v -> PicoRV32
PicoRV32 -> Wishbone -> wbxbar -> GPIO / wb_ram_ip
```

## Три адреса, которые нужно помнить

```text
0x00000000  RAM с программой
0x10010000  GPIO
0x10020000  дополнительная RAM задания 2
```
